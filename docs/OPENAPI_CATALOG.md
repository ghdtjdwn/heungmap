# 08. OpenAPI 카탈로그

## 문서 목적
한국관광공사 OpenAPI 후보를 한곳에 모으고, 흥할지도에서 실제로 검토할 API와 참고만 할 API를 구분한다. 기능 수를 늘리기 위해 API를 무리하게 붙이지 않고, 과제 9번의 핵심 흐름과 심사기준에 기여하는지 판단하는 기준으로 사용한다.

## 스냅샷 범위와 주의
- 기준일: **2026-09-04**
- 출처: 팀이 공공데이터포털 검색 결과에서 확인해 전달한 목록
- 검색 결과: 총 32건이며, **한국관광공사 제공 28건 + 다른 기관 제공 4건**이다.
- 조회수와 활용신청 수는 기준일 당시 값이며 계속 변한다. API를 실제로 사용하기 전에는 공공데이터포털 상세 페이지에서 최신 명세, 호출 제한, 이용허락범위, 데이터 기간을 다시 확인한다.
- 목록에 표시된 `XML·JSON`은 제공 형식이다. 구현에서는 특별한 이유가 없으면 JSON을 사용한다.
- 활용신청은 필요한 API부터 최소한으로 진행한다. API 개수가 많다고 데이터 활용 적절성 점수가 자동으로 올라가는 것은 아니다.

## 흥할지도 활용 우선순위

| 등급 | 의미 | API |
|---|---|---|
| A — 데이터 게이트·필수 | 프로젝트 성립 여부와 공사 OpenAPI 필수 요건에 직접 연결 | 국문 관광정보 서비스, 빅데이터 지역별 방문자수 |

| 외부 참고 | 한국관광공사 API는 아니며 특정 기능에 필요할 때만 검토 | 문체부 보도자료, 테마휴게소, 텐트촌, 물과 여행 정보 |

## 데이터 해석상 중요한 한계

### 지역별 방문자수
- 제공기관 설명에서 방문자는 일상생활권을 벗어나 한 장소에 일정 시간 머문 사람을 뜻한다.
- 데이터 특성상 정확한 방문목적을 알 수 없으므로 방문자를 관광객 또는 특정 축제 관람객과 동일하게 취급하면 안 된다.
- 데이터 스파이크에서 시간·공간 단위, 축제 없는 기준 기간, 같은 지역의 동시 행사 영향을 확인한 뒤 라벨 정의를 결정한다.

### 관광지 집중률 방문자 추이 예측
- KT 이동통신 데이터와 2018년 이후 패턴을 이용해 조회일 기준 향후 30일을 예측한 값이다.
- 가장 붐비는 시기를 100으로 둔 상대 집중률이며 실제 방문자 수가 아니다.
- 흥할지도의 학습 정답으로 사용하지 않고, 방문객 화면의 보조 지표나 자체 예측과의 비교 자료로만 검토한다.

### 관광지별 연관 관광지·기초지자체 중심 관광지
- Tmap 내비게이션 차량 이동 데이터를 기반으로 하므로 실제 연계 방문자 수와 차이가 날 수 있다.
- 도보·대중교통 이용자의 행동을 대표하지 않는다.
- 전달받은 목록에서 연관 관광지 정보의 제공 기간은 2024년 5월부터 2025년 4월까지로 안내됐다. 실제 사용 전 최신 제공 기간을 확인한다.

### 사진·동영상
- API 응답에 URL이 있다고 해서 모든 매체를 제한 없이 재배포할 수 있다는 의미는 아니다.
- 콘텐츠별 이용허락범위, 출처 표시, 인물·상표·저작권 조건을 확인한 뒤 사용한다.

## 현재 추천 조합

### 데이터 스파이크
1. **국문 관광정보 서비스**: `searchFestival2`로 축제명·기간·지역·좌표·`contentid` 확보
2. **빅데이터 지역별 방문자수**: 같은 지역과 기간의 방문자 시계열 확보
3. 두 데이터를 결합하고 매칭률뿐 아니라 라벨의 의미와 품질을 검증

### Tier 0
1. 국문 관광정보 서비스로 실제 축제 목록·상세·주변 관광정보 제공
2. 검증된 방문자 자료로 규칙 기반 수요 지수 계산
3. 관광지 집중률 예측은 의미가 맞을 때만 방문객 혼잡도 보조 자료로 표시

### Tier 1 이후
1. 지역별 관광 자원 수요·관광 다양성·관광 수요 강도를 추가 특성 후보로 검증
2. 연관·중심 관광지 정보로 개최지 또는 연계 코스 추천 강화
3. 관광사진·무장애·다국어 정보는 핵심 기능과 안정성이 완성된 뒤 확장
