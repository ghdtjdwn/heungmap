# 기획자 기능 계획

## 목표

기획자가 정해진 선택지와 `기타` 입력을 따라 행사 조건을 작성하면, 흥할지도의 수요 예측 모델과
TourAPI·관광 데이터랩 등 근거 데이터를 먼저 계산한다. LLM은 그 구조화된 결과를 바탕으로 실행 가능한
행사 기획안, 대안과 우선 보완점을 제안한다.

현재 문서는 넣을 수 있는 후보를 넓게 기록한 설계 초안이다. 실제 화면에는 데이터 가용성, 사용자 부담,
심사 기여도와 구현 시간을 검토해 필요한 항목만 남긴다.

## 핵심 원칙

- 입력은 가능한 한 선택형으로 제공하고 각 항목에 `기타 직접 입력`, `아직 모름`, `추천받기`를 둔다.
- 한 화면에 모든 항목을 노출하지 않고 답변에 따라 다음 질문이 달라지는 단계형 form을 사용한다.
- 예측 모델이 수요와 수치 범위를 계산하고, LLM은 그 값을 임의로 바꾸지 않는다.
- LLM의 사실·예측·가정·추천을 화면에서 구분한다.
- 근거 데이터가 없으면 모른다고 표시하고 장소, 비용, 법규나 성과를 지어내지 않는다.
- 대형 기획자와 소규모 독립 기획자·가수에게 질문 깊이와 결과 수준을 다르게 제공한다.
- LLM 실패 시에도 입력 요약, 규칙 기반 score와 수요 결과는 볼 수 있어야 한다.

## 전체 처리 흐름

```text
기획자 단계형 입력
        ↓
입력 검증·단위 통일·누락 확인
        ↓
TourAPI·관광 데이터랩·날씨·장소 등 근거 수집
        ↓
공유 AI 모델의 수요 baseline·행사 uplift·예측 범위
        ↓
수용인원·예산·편의시설 등 확정적 계산
        ↓
구조화된 Planning Context 생성
        ↓
LLM 기획 추천 생성
        ↓
schema·근거·금지 주장 검증
        ↓
기획안·대안 비교·what-if·수정 반복
```

LLM을 form 입력 중 매번 호출하지 않는다. 초안 저장과 계산은 별도로 처리하고, 사용자가 `분석하기`를
눌렀을 때 검증된 입력 snapshot으로 예측과 추천을 실행한다.

## 입력 UX 공통 규칙

- 단계와 진행률을 표시한다.
- 모든 숫자에는 원·명·일·시간·제곱미터 등 단위를 표시한다.
- 범위를 모를 때는 최솟값·최댓값 또는 규모 구간을 선택할 수 있게 한다.
- 선택한 답변에 필요한 후속 질문만 표시한다.
- 이전 단계로 이동해도 답변을 유지한다.
- 자동 저장, 임시 저장, 복사본 만들기와 마지막 저장 시각을 제공한다.
- 필수 항목, 선택 항목과 추천 정확도를 높이는 항목을 구분한다.
- 민감하거나 정확한 금액을 넣기 어렵다면 금액 구간으로 입력할 수 있게 한다.
- 제출 전에 전체 입력 요약과 수정 화면을 제공한다.
- 각 section 마지막에 `기타 고려사항` 자유 입력을 둔다.

## 입력 후보 전체 목록

### 1. 기획자와 기획 상태

- 기획자 유형: 지자체, 공공기관, 기업, 행사 대행사, 공연기획사, 장소 운영자, 동아리, 독립 기획자, 가수·아티스트, 기타
- 팀 규모와 의사결정자 수
- 관련 행사 기획 경험: 없음, 1~2회, 3~5회, 6회 이상
- 현재 단계: 아이디어, 사전 조사, 예산 신청, 장소 탐색, 섭외, 홍보 준비, 예매 중, 최종 준비
- 이미 확정된 항목과 변경 가능한 항목
- 최종 의사결정 기한
- 추천을 받을 목적: 아이디어, 타당성 검증, 수요 예측, 장소 비교, 예산 배분, 홍보, 운영, 위험 점검, 전체 기획
- 결과의 상세 수준: 빠른 진단, 표준 기획안, 상세 실행안
- 기획자의 가장 큰 걱정과 우선 해결 질문
- 행사·예산·관객 정보의 공개 가능 범위

### 2. 행사 기본 정보

- 행사명 또는 임시 프로젝트명
- 행사 유형: 축제, 콘서트, 클럽 공연, 버스킹, 팬미팅, 전시, 박람회, 컨퍼런스, 체험, 플리마켓, 지역 행사, 기타
- 행사 목적: 수익, 지역 활성화, 관광 유입, 브랜드 홍보, 팬 확대, 커뮤니티, 문화 향유, 교육, 사회공헌, 기타
- 핵심 주제·테마·장르
- 행사 한 줄 설명
- 신규·반복·연례 행사 여부와 개최 횟수
- 단독 행사·다른 행사 연계 여부
- 오프라인·온라인·hybrid 여부
- 무료·유료·부분 유료 여부
- 공개 행사·초대 행사·회원 전용 여부
- 일회성·순회·정기 개최 여부
- 성공했다고 판단할 핵심 목표와 KPI
- 반드시 포함할 요소와 절대 제외할 요소

### 3. 목표 이용객

- 핵심 이용객 유형
- 예상 연령대와 관심사
- 개인·친구·연인·가족·단체 방문 비중 예상
- 지역 주민·타지역 방문객·외국인 목표 비중
- 신규 이용객·기존 팬·회원 비중
- 학생·직장인·관광객 등 생활 유형
- 구매력·허용 티켓 가격 구간
- 행사 정보를 주로 접하는 채널
- 방문을 결정하는 핵심 이유와 포기하는 이유
- 체류 예상시간과 행사 전후 활동
- 필요한 언어와 안내 수준
- 장애인, 고령자, 임산부, 영유아 동반자 등 접근성 요구
- 목표 이용객 수, 최소 성공 인원과 최대 수용 인원
- 이용객 persona와 대표 방문 시나리오

개인을 식별하거나 민감정보를 수집하지 않고 공개·집계된 통계나 기획자의 가정만 사용한다.

### 4. 일정

- 희망 연도·월·날짜 또는 후보 날짜
- 날짜 확정 여부와 변경 가능 범위
- 행사 시작·종료일과 전체 기간
- 일별 시작·종료 시각
- 입장 시작, 프로그램 시작과 퇴장 예상시각
- 설치·리허설·철거 일정
- 평일·주말·공휴일·연휴 선호
- 낮·저녁·심야 선호
- 방학·휴가철·성수기·비수기 고려
- 우천 대체일과 연기 가능 여부
- 출연진·장소·허가 일정 제약
- 예매·홍보를 시작할 수 있는 날짜
- 날짜별 우선순위와 피해야 할 날짜
- 동일 기간 경쟁 행사 허용 수준

### 5. 지역과 장소

- 희망 광역·기초지자체·동네 또는 후보 지역
- 특정 지역을 선택한 이유
- 장소 확정 여부와 후보 장소
- 장소 유형: 야외광장, 공원, 공연장, 클럽, 경기장, 학교, 전시장, 복합문화공간, 카페, 상점, 기타
- 실내·실외·혼합 여부
- 좌석·스탠딩·혼합 운영
- 공식 수용인원과 목표 운영 인원
- 행사장 면적, 무대·객석·부스 배치 가능 면적
- 대관료와 추가 시설 비용
- 이용 가능 시간과 소음·영업시간 제한
- 전력·급수·Wi-Fi·냉난방·조명·음향·영상 장비
- 무대, 대기실, 물류 반입구와 창고
- 출입구·비상구·동선 분리 가능 여부
- 화장실·휴게·수유·의료·물품보관 시설
- 지하철·버스·기차·공항·고속도로 접근성
- 주차 가능 대수와 임시 주차 가능성
- 주변 숙박·음식점·카페·편의점·관광지
- 휠체어 접근, 경사, 엘리베이터와 장애인 화장실
- 장소별 장점·단점과 변경 가능 여부
- 장소를 정하지 못한 경우 추천받을 지역·거리 범위

### 6. 규모와 공간 운영

- 목표 방문자·입장객·동시 체류 인원
- 회차 수와 회차별 수용인원
- 좌석 등급과 구역 수
- 무대·관람·부스·휴식·대기·식음 공간 비율
- 예상 입장·퇴장 집중 시간
- 대기열 허용 길이와 예상 대기시간 목표
- 입장 확인 방식: 무료, 명단, QR, 종이 티켓, 현장 결제 등
- 재입장 허용 여부
- 관객·출연진·staff·물류 동선
- 혼잡 구역과 병목 예상 위치
- 우천·폭염·한파 시 수용 계획
- 매진·초과 방문·노쇼 대응

### 7. 프로그램과 콘텐츠

- 프로그램 유형과 전체 수
- 핵심 프로그램·헤드라이너·대표 콘텐츠
- 프로그램별 시작·종료·준비 시간
- 동시 진행 프로그램과 stage 수
- 공연·체험·전시·토크·판매·식음 비중
- 참여형·관람형 콘텐츠 비율
- 어린이·가족·외국인·장애인용 프로그램
- 유료·무료 프로그램 구분
- 사전 신청·현장 참여·선착순 여부
- 프로그램별 수용인원과 회전율
- 촬영·streaming·녹화 여부
- 굿즈·포토존·이벤트·경품 계획
- 지역 관광지·상권·예술가와 연계 가능성
- 프로그램 우선순위와 예산 부족 시 제외 순서

### 8. 출연진·연사·파트너

- 출연진·가수·연사·진행자 후보와 확정 여부
- 장르·인지도·예상 팬층
- 출연료·교통·숙박·기술 rider 예상 범위
- 출연 가능 날짜와 대체 출연진
- 단독·공동 출연과 공연 순서
- 지역 예술가·신인·헤드라이너 구성
- 출연진별 홍보 협조 가능 범위
- sponsor·협찬사·지역 상인·기관 partnership
- 섭외 담당자와 계약 마감
- 출연 취소·지각·장비 문제 fallback
- 저작권·초상권·촬영·음원 사용 조건

### 9. 티켓과 가격

- 무료·유료·부분 유료 여부
- 총 판매·배포 수량과 좌석 등급별 수량
- 정상가·조기예매·현장가·할인 가격
- 무료 초대·관계자·sponsor 배정 비율
- 예매 시작·종료일과 판매 채널
- 취소·환불·양도·재입장 정책
- 구매 수량 제한과 본인확인 여부
- 목표 판매율·최소 판매량·매진 목표시점
- 현재 판매량·판매속도·취소율
- 대기자·알림 신청·관심 등록 수
- 노쇼 예상과 초과 예약 정책
- 가격을 정하지 못한 경우 목표 이용객과 비용을 반영한 추천 요청

리셀 가격 예측이나 암표 거래를 지원하는 기능은 포함하지 않는다.

### 10. 예산과 수익

- 총예산 최솟값·기준값·최댓값
- 확보 예산과 미확보 예산
- 자기자본·지원금·후원·협찬·투자·티켓 수익 구성
- 장소 대관·시설·장비·무대·음향·조명 비용
- 출연진·진행자·staff·외주 인건비
- 홍보·광고·콘텐츠 제작비
- 보험·경비·안전·의료·허가 비용
- 교통·숙박·식비·물류 비용
- 예매·결제 수수료
- 청소·폐기물·화장실·전기·통신 비용
- 예비비와 환불·취소 손실 대비금
- 티켓·굿즈·식음·부스·sponsor 예상 수익
- 목표 매출·목표 이익·허용 손실
- 손익분기 관객 수
- 예산 고정 항목과 조정 가능한 항목
- 비용 절감 우선순위와 품질을 유지할 항목

정확한 비용 자료가 없으면 LLM이 임의 금액을 확정하지 않고 범위, 필요한 견적 항목과 확인 순서를 제안한다.

### 11. 홍보와 판매

- 행사·주최자·출연진의 현재 인지도
- 공식 홈페이지와 SNS 채널
- 보유 follower·subscriber·회원·이메일 규모
- 홍보 시작일과 전체 기간
- 광고 예산과 사용할 채널
- Instagram, YouTube, TikTok, X, 블로그, 커뮤니티, 보도자료, offline 홍보 등 채널 선택
- 콘텐츠 제작 가능 인력·빈도·format
- 출연진·partner 공동 홍보 가능성
- 지역 상권·학교·기관·동호회 연계
- 검색광고·SNS 광고·옥외광고·언론 홍보 계획

## AI 모델 결과 입력

LLM에 넘길 예측 결과는 [`MODEL_PLAN.md`](MODEL_PLAN.md)의 공통 prediction 계약을 사용한다.

- 수요 결과의 종류와 단위
- 지역 평상시 수요 baseline
- 행사 uplift 중앙값과 범위
- `p10`, `p50`, `p90` 예측 범위
- 흥행 가능성 score와 혼잡·티켓 수요 등급
- 장소 수용인원 대비 예상 점유율
- 데이터 충분성·신뢰도·학습 범위 밖 여부
- 상승·하락 영향 요인
- 사용한 데이터 출처·갱신 시각·model version
- 규칙 fallback 사용 여부와 해석 한계

## Planning Context

LLM에는 원본 form과 API 응답을 그대로 던지지 않고 다음 구조로 정리한 context를 전달한다.

```text
planner_profile
event_brief
fixed_constraints
flexible_options
target_audience
schedule_candidates
location_and_venue_candidates
program_and_performers
ticket_and_budget
marketing_and_operations
safety_accessibility_sustainability
prediction_result
tourism_and_local_evidence
missing_information
requested_decisions
```

각 값에는 가능하면 `source`, `as_of`, `unit`, `value_type`, `confidence`와 `limitation`을 붙인다.
`value_type`은 `user_input`, `verified_fact`, `derived_value`, `model_prediction`, `assumption`으로 구분한다.
공통 행사·예측·evidence field와 분석 endpoint는 [`SHARED_SPEC.md`](SHARED_SPEC.md)를 따른다.

## LLM 역할

LLM이 수행한다.

- 입력과 목표를 기획 brief로 요약
- 예측값과 영향 요인을 사람이 이해할 수 있게 설명
- 고정 제약을 지키는 실행안과 대안 생성
- 대형·소규모 기획자 상황에 맞는 우선순위 조정
- 빠진 정보와 추가 확인 질문 제시
- 날짜·장소·규모·예산·프로그램·홍보·운영 대안 비교
- 위험과 대응책을 구조화
- 실행 일정·담당·KPI·체크리스트 초안 생성
- 추천별 근거·가정·예상 영향·비용 수준·난이도 표시

LLM이 수행하지 않는다.

- 예측 모델의 숫자를 임의로 변경하거나 새 수요 수치를 계산
- 존재하지 않는 장소·시설·지원금·법규·허가·가격을 사실처럼 생성
- 모델 신뢰도가 낮은 결과를 확정적으로 표현
- 사용자가 입력하지 않은 민감정보를 추론
- 안전·법률·보험 적합성을 최종 승인
- 실제 견적·계약·섭외가 끝난 것처럼 표현

## 추천 결과 구조

### 1. 한눈에 보는 진단

- 행사 목표와 핵심 조건 요약

## 추천 항목의 공통 schema

각 추천은 자유로운 문단만 반환하지 않고 최소한 다음 구조를 갖는다.

```text
recommendation_id
category
title
action
priority
reason
evidence_refs
assumptions
predicted_impact
cost_level
difficulty
deadline
dependencies
risks
confidence
requires_human_review
```

LLM 결과는 server에서 schema와 evidence reference를 검증한다. 필수 field가 없거나 입력에 없는 근거를
참조하면 응답 전체를 거부하고 frontend가 검증된 규칙 fallback으로 전환한다. 새 수요·비용·장소·법규
사실을 생성하지 말라는 제약을 prompt와 사람 확인 표시에도 함께 적용한다.

기획자 담당자가 단독으로 확정하지 않는 범위는 label 정의, model 채택, 공통 prediction 계약 변경과
사용자 화면에도 영향을 주는 event schema다. 이 항목은 공유 데이터·예측 계약 관리자와 상대 담당자가 함께
검토한다.

## 구현 단계

### 현재 입력 범위 분류

| 분류 | 항목 |
| --- | --- |
| MVP 필수 | 기획자 유형·기획 단계, 행사 유형·목적·테마, 목표 이용객 |
| 선택 입력 | 일정·지역·장소·수용 규모, 티켓·예산, 프로그램·홍보·운영·안전·접근성, 제약·대안 수 |
| 자체 model 이후 | 학습 예측·SHAP, 데이터 게이트를 통과한 추가 feature |
| 현재 제외 | 로그인·server draft·공개 공유, 문서 upload, 결제·예매, 법률·안전 승인, 확인되지 않은 공식 수용인원 자동 추정 |

선택 입력은 비워도 흐름을 완료할 수 있고 결과의 `missing_information`과 확인 순서로 돌려줍니다. form은
7단계, 내보내기는 Markdown·JSON·browser PDF 인쇄로 확정합니다. What-if는 중복 LLM 비용을 만들지 않고
mock prediction과 규칙 항목만 비교하며, 전체 LLM 보고서가 필요하면 변경안을 새 기획 version으로 분석합니다.

### 단계 0 — 입력과 template

- 핵심 입력 10~15개와 `기타`, `모름`, `추천받기`
- 입력 검증과 요약
- mock prediction response
- 규칙 기반 진단과 고정 기획 template

### 단계 1 — 실제 데이터·예측 연결

- TourAPI와 관광 데이터랩 evidence
- 지역 baseline·행사 uplift 또는 규칙 score
- 예측 범위·영향 요인·신뢰도
- 장소·편의시설 근거

### 단계 2 — LLM 기획 추천

- Planning Context와 structured output
- 근거·가정·추천 구분
- 대형·소규모 기획자별 결과 깊이
- 실패·timeout·비용 제한 fallback

### 단계 3 — 비교와 반복

- 날짜·장소·규모·예산 what-if
- 추천안·차선안 비교
- 기획안 version과 변경 이력
- 공유·PDF 등 내보내기 후보

## 완료 조건

- 기획자는 모르는 항목이 있어도 필수 흐름을 완료할 수 있다.
- 입력을 수정하면 어떤 예측과 추천이 바뀌었는지 알 수 있다.
- 모델 수치와 LLM 설명이 충돌하지 않는다.
- 모든 핵심 추천에 근거, 가정, 신뢰도와 사람 확인 필요 여부가 있다.
- 대형·소규모 기획자 scenario에서 서로 다른 우선순위와 실행안을 제공한다.
- TourAPI 활용 지점과 관광 데이터랩·자체 모델·LLM의 역할을 구분해 설명할 수 있다.
- model이나 LLM이 실패해도 입력 초안과 baseline 결과가 보존된다.
- 실제 구현한 범위와 아직 후보인 항목을 화면과 문서에서 구분한다.
